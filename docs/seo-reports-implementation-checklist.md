# SEO отчёты — детальный чеклист внедрения

**Референсы (ориентир, не копируем 1в1):**
- Структура/полнота: [seo-reports.ru/examples/complex](https://seo-reports.ru/examples/complex)
- Фичи (комменты, DOCX, история): [rpt.im/8xxcIHrqU8iO](https://rpt.im/8xxcIHrqU8iO)

**Продуктовый принцип Titlo:** референсы = минимальная планка по блокам данных.  
Мы делаем **отчёт нового уровня**: живой web-first, с автосбором из модулей кабинета, целями KPI, инсайтами «что случилось / что делать», клиентским порталом и белым лейблом агентства — без уродской вёрстки rpt.im и без «просто свалки графиков».

**Статус прогресса:** `221 / 221` выполнено · `0` осталось

**Правило отчётности в работе:** после каждой порции задач писать:  
`выполнено X / всего 221 · осталось Y · закрыты: …`

## Продуктовые отличия (зачем мы лучше)

| У референсов | У Titlo (цель) |
|--------------|----------------|
| Ручной/полуручной сбор цифр из кучи кабинетов | Один проект = связка модулей Titlo + интеграции, генерация в 1 клик |
| Статичный PDF/HTML «на сегодня» | Живой web-отчёт + PDF как экспорт; клиент листает, фильтрует, оставляет реакции |
| Текст «проделанная работа» пишут руками | Автоподтягивание фактов из аудита/чеклиста/мониторинга + редактирование |
| Нет целей | KPI-цели на период (трафик / TOP-10 / заявки) и % выполнения |
| Слабые инсайты | Авто-инсайты: аномалии, победители/проигравшие запросы и страницы, «что чинить» |
| Уродская вёрстка / однотипные блоки | Дизайн-система отчёта: иерархия, sparklines, единые дельты, мобильный first |
| Facebook в комплексе как must | Meta — опциональный канал; РФ-ядро: Яндекс + VK + наш мониторинг |
| Нет связи с «здоровьем сайта» | Блок технического здоровья из Site Audit / аптайм / DNS / SSL |
| Клиент только скачал файл | Публичная ссылка + PIN + комментарии клиента + «одобрить отчёт» |

**Не делаем вслепую:** не тащим Meta/Facebook в MVP; не копируем каждую бесполезную таблицу rpt.im; пустые секции без интеграции — скрываем, а не рисуем нули.

### Правило секций и источников (важно)

Реализуем **все блоки отчёта в коде** (layout, таблицы, графики, тексты), но каждый блок завязан на источник и флаги:

1. **Feature / section toggle** на уровне проекта или шаблона: менеджер может вкл/выкл секцию вручную.  
2. **Авто-скрытие:** если источник `not_connected` / `error` / данных нет — секция **не маячит** в клиентском отчёте (ни оглавление, ни пустые нули).  
3. **В кабинете менеджера** такие секции видны серыми: «Директ — не подключён» / «GSC — ошибка токена», с CTA подключить.  
4. **Демо-режим** отдельно: может показывать фейковые данные для витрины; в боевых отчётах — никогда.  
5. Новые интеграции потом = заполняем тот же блок живыми данными, без переделки вёрстки.

Итого: UI секций делаем заранее, интеграции — волнами; клиент видит только то, что реально работает.
